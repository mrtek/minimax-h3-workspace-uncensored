# Minimax H3 Workspace (Uncensored Edition) — Архитектура, руководство и история доработок

> **Назначение этого документа**: полное техническое описание проекта для разработчиков и AI-ассистентов. Содержит структуру репозитория, устройство всех компонентов, ключевые доработки Uncensored-версии, детальный разбор устранённых критических багов (включая зомби-процессы ядра Windows и логику чатов агента), а также инструкцию по сборке и план внедрения автозагрузки LoRA.

## 3. Архитектура модулей программы (`app/`)

### `app/main.py` — Точка входа приложения
- **Windows Job Object (`init_job_object`)**: процесс регистрируется в Job Object с флагом `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE (0x2000)`. При падении или закрытии главного процесса операционная система гарантированно убивает всех его потомков (`llama-server.exe`, `whisper.exe`, дочерние питоновские процессы ComfyUI).
- **Выбор порта (`free_port`)**: перебирает порты начиная с 8765. Проверяет не только отсутствие слушателя через `connect_ex`, но и возможность реально открыть и привязать TCP-сокет с флагом `SO_REUSEADDR`.
- **Серверный поток (`ServerThread`)**:
  - Поднимает `aiohttp.web.AppRunner(server.build_app(), shutdown_timeout=0.1)` в отдельном потоке с новым циклом событий `asyncio.new_event_loop()`.
  - Запускает `web.TCPSite(self.runner, "127.0.0.1", port, reuse_address=True)`.
  - **Корректный shutdown (`shutdown`)**:
    1. Принудительно закрывает слушающий TCP-сокет (`self.site._server.close()` и `await wait_closed()`), освобождая порт в драйвере `afd.sys`.
    2. Очищает раннер с таймаутом 1.0 с (`await runner.cleanup()`).
    3. Отменяет все фоновые задачи цикла событий.
- **Жизненный цикл окна и защита от зависаний (`do_exit`)**:
  - Объединяет событие закрытия окна WebView2 (`window.events.closed`) и выход из `main()` через потокобезопасный `threading.Lock`.
  - Запускает 3.5-секундный сторожевой таймер (`threading.Timer`), вызывающий аварийный выход, если что-то застрянет.
  - Дожидается штатного `srv.shutdown()` и затем вызывает `hard_exit(code)`.

### `app/server.py` — Ядро бэкенда (`App`)
- Маршрутизация REST API и WebSocket:
  - `/api/status`, `/api/system` — статус ComfyUI, мониторинг GPU/VRAM/RAM/диска.
  - `/api/generate/*` — очереди генерации (Image-to-Video, Lipsync, Референсы, Актёрская игра, Экшн, Длинное видео).
  - `/api/events` — WebSocket-канал реального времени для прогресса, очереди и статусов.
  - `/api/file/{id}` — отдача видео/картинок из библиотеки или ComfyUI output через `web.FileResponse`.
  - `/api/agent/chat` — стриминговый SSE-эндпоинт (`text/event-stream`) общения с локальным агентом. Перед вызовом освобождает VRAM ComfyUI через `/free` и стартует `llama-server`.
  - `/api/agent/chats`, `/api/agent/chats/{id}` — CRUD операции с историей чатов (JSON-файлы в `data/chats/`).
  - `/api/agent/skills` — динамическая загрузка, включение и парсинг папок со скиллами (файлы `SKILL.md`).
  - `/api/loras/*` — управление списком LoRA и их метаданными.
- **Очистка ресурсов (`App.stop`)**: закрывает клиентские сессии, WebSocket-клиенты, останавливает фоновые процессы `comfy` и `llama-server` с таймаутом `asyncio.wait_for(..., timeout=2.0)`.

### `app/agent.py` — Управление LLM-агентом
- Класс `LlamaServer`: запуск и мониторинг `llama-server.exe` с аргументами `--port`, `--model`, `--mmproj`, `--n-gpu-layers`, `--ctx-size`.
- Автодетекция моделей GGUF и файлов `mmproj` (включая поиск любых паттернов `*mmproj*.gguf`).
- Поддержка кастомных сторонних моделей из любой указанной пользователем папки.
- Форматирование сообщений в формат Chat Completions OpenAI API (`to_openai`).
- Инжекция активированных скиллов и активных LoRA в системный промпт агента.

### `app/ui/index.html` — Одностраничный интерфейс (SPA)
- Полностью автономный UI (HTML, CSS, JS в одном файле).
- Разделы:
  1. **Агент**: интеллектуальный генератор промптов по скиллам, карточкам персонажей и референсам.
  2. **Image-to-Video**: базовая генерация видео по первому/последнему кадру и тексту.
  3. **Lipsync / клип**: синхронизация губ по аудиофайлу и референсу.
  4. **Референсы**: видео с сохранением персонажей, локаций и голоса (Singularity Ref2V).
  5. **Актёрская игра**: диалоги, эмоции, мимика по образцу (10 шагов).
  6. **Экшн-сцены**: динамические бои, бег, погони (Hybrid 8+4 шага).
  7. **Длинное видео**: клипы по сценам (Pika/tail continuation) с сохранением преемственности.
  8. **Картинка по тексту / Правка**: Krea 2, FLUX.2 klein, Qwen 2.1.
  9. **Очередь, Библиотека, Монтаж, Модели**: управление задачами, предпросмотр результатов, склейка клипов, менеджер весов.

### `app/loras_registry.py` & `app/civitai_browser.py`
- Интеграция с Civitai API и Hugging Face для поиска и скачивания LoRA под MiniMax H3.
- Форматирование синтаксиса триггерных слов и силы LoRA для подачи агенту.

## 5. Детальный разбор ключевых исправлений (v1.1.10 – v1.1.11)

### Проблема №1: «Процесс висит в Диспетчере задач после закрытия и не убивается»
- **Симптом**: после закрытия окна `MinimaxH3Workspace.exe` оставался в списке процессов Диспетчера задач и Process Explorer. Команда `taskkill /F /PID <pid>` возвращала ошибку `Экземпляр задачи не запущен`. При повторном запуске приложение открывало чёрное окно или висло на соединении.
- **Анализ ядра через `NtQuerySystemInformation` и WinDbg/Process Explorer**:
  - У процессов был флаг `HasExited = True` и код выхода `0` или `1`. То есть код приложения уже завершился.
  - Однако дескрипторы на объект `EPROCESS` удерживались процессами `System` (PID 4) и `csrss.exe` (PID 980).
  - Причина: сокеты портов 8765 и 8766 оставались открытыми в сетевом драйвере ядра `afd.sys` в состоянии `LISTENING`. В них висели незавершённые асинхронные IRP-пакеты `AcceptEx` от Windows Proactor EventLoop.
  - Когда приложение вызывало принудительный `hard_exit(0)` (`kernel32.TerminateProcess`), ядро Windows не могло очистить объект процесса до тех пор, пока драйвер сокетов не завершит IRP, превращая процесс в неудаляемый «зомби».
  - Дополнительно служба `PcaSvc` (Program Compatibility Assistant в `svchost.exe`) перехватывала незавершённый сброс ресурсов и вешала дополнительный дескриптор.
- **Исправление**:
  1. В `ServerThread.shutdown()` введено обязательное закрытие слушающего сервера:
     ```python
     if hasattr(self.site, "_server") and self.site._server:
         self.site._server.close()
         await asyncio.wait_for(self.site._server.wait_closed(), timeout=0.5)
     ```
  2. В `AppRunner` установлен `shutdown_timeout = 0.1` (чтобы сервер не ждал 60 секунд завершения длинных HTTP-соединений).
  3. Закрытие процесса переведено на потокобезопасную функцию `do_exit`, где сначала штатно гасится `srv.shutdown()`, и только после закрытия всех сокетов вызывается `hard_exit(0)`.
  4. В `free_port()` добавлена проверка реального связывания сокета с `SO_REUSEADDR`, чтобы даже при наличии сторонних помех выбирался исключительно рабочий порт.

### Проблема №2: «Не могу выбрать старые чаты в Агенте, всё зависает»
- **Симптом**: во время генерации или после ошибки пользователь нажимал на старый чат в истории слева — ничего не происходило, кнопка залипала в состоянии «Стоп», поле ввода показывало «Отправляем...».
- **Причина**:
  1. При нажатии «Стоп» или клике на другой чат вызывался `AG.ctrl?.abort()`. Однако в движке WebView2 этот вызов прерывал сетевой `fetch`, но **не прерывал уже открытый поток чтения** `const reader = r.body.getReader(); reader.read()`.
  2. Переменная `AG.busy` оставалась равной `true`, кнопка не меняла надпись на «Отправить», а любые клики по старым чатам игнорировались.
  3. Функция `saveChat()` запускалась асинхронно из блока `catch` прерванного запроса. Если пользователь в этот момент успевал переключить `AG.id`, прерванный черновик перезаписывал чужой открытый чат.
  4. В `openChat` отсутствовал `try/catch`. Если сервер возвращал ошибку или в `agCtx()` происходило обращение к `RM[AG.target].S.dur` для несуществующего режима, скрипт молча падал.
- **Исправление**:
  1. Написана отдельная функция `agStop()`:
     ```javascript
     function agStop() {
       if (AG.busy) {
         try { AG.ctrl?.abort(); } catch {}
         try { AG.reader?.cancel(); } catch {} // Немедленно отменяет блокирующий reader!
         AG.busy = false;
         $('#agSend').textContent = 'Отправить';
         ...
       }
     }
     ```
  2. Вызов `agStop()` добавлен в начало `openChat()`, `newChat()` и при клике на кнопку «Стоп».
  3. Добавлена изоляция чата: `if (sendChatId === AG.id)` — прерванный ответ сохраняется только в тот чат, из которого он был запущен.
  4. Весь метод `openChat()` обёрнут в `try/catch` с отображением всплывающих уведомлений `toast()`.
  5. В `agCtx()` добавлен безопасный fallback: `RM[AG.target] ? ... : 'Длительность 5 с.'`.

### Проблема №3: Зависание агента из-за занятой памяти GPU после генерации видео
- **Симптом**: после рендера видео в ComfyUI агент не отвечал, видеопамять оставалась забита под 100%.
- **Причина**: модель FastH3 оставалась загруженной в VRAM ComfyUI (~10-14 ГБ), и для запуска `llama-server.exe` (~6 ГБ) не хватало памяти, что приводило к сбросу в медленный своп RAM/диска или дедлоку.
- **Исправление**:
  - В `server.py` после завершения каждого задания ComfyUI автоматически отправляется запрос `POST /free` с `unload_models: True, free_memory: True`.
  - В `h_agent_chat` перед стартом `llama-server` сервер ожидает реального освобождения VRAM через опрос `/system_stats`.

## 6. Процедура сборки и выпуска обновлений

Все скрипты сборки автоматизированы.

### Шаг 1. Компиляция Python в EXE через PyInstaller
```powershell
pyinstaller --noconfirm app/build/h3studio.spec
```
- Спецификация `app/build/h3studio.spec` собирает проект в `dist/MinimaxH3Workspace/`.
- Синхронизация файлов в папку Inno Setup:
```powershell
Copy-Item -Recurse -Force 'dist/MinimaxH3Workspace/*' 'app/build/dist/MinimaxH3Workspace/'
```

### Шаг 2. Компиляция инсталлятора через Inno Setup
```powershell
& 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe' app/build/h3studio.iss
```
- Результат: готовый инсталлятор `app/build/output/Minimax.H3.Workspace.Uncensored-Setup_v<VERSION>.exe`.

### Шаг 3. Публикация релиза на GitHub
В проекте настроен скрипт (на примере `create_github_release_v111.py`), использующий токен из `git credential`:
1. Создаёт тег и пушит в `myfork`:
   ```powershell
   git tag v1.1.X
   git push myfork v1.1.X
   ```
2. Отправляет запрос к GitHub REST API (`https://api.github.com/repos/mrtek/minimax-h3-workspace-uncensored/releases`), создаёт релиз и загружает бинарник `.exe`.

## 7. План следующего этапа: Автозагрузка LoRA по умолчанию

Пользователь планирует отобрать лучшие LoRA для Uncensored-версии (реализм людей, животных, шерсти собак/кошек, динамика).

### Где и как это будет интегрировано в код:
1. **Реестр рекомендуемых LoRA в `app/catalog.py`**:
   - Добавить словарь `DEFAULT_UNCENSORED_LORAS` со ссылками на проверенные репозитории (Hugging Face / Civitai direct download), именами файлов, триггерными словами и весами по умолчанию.
2. **Скачивание при первичной установке (`app/setup.py` / `app/downloader.py`)**:
   - В мастер первой установки (`setup_wizard`) добавить чекбоксы выбора наборов LoRA («Реализм и детализация», «Животные и шерсть», «Анатомия и Uncensored»).
   - Загружать файлы напрямую в папку `ComfyUI_windows_portable\ComfyUI\models\loras\`.
3. **Автоматическая регистрация в `app/loras_registry.py`**:
   - При старте приложения сканировать папку `models/loras/` и автоматически включать скачанные дефолтные LoRA в `config.json`.
4. **Информирование агента**:
   - Модуль `format_loras_for_agent()` уже готов: он автоматически передаёт список всех активных LoRA и их триггерные слова в системный промпт модели Gemma 4, поэтому агент сразу начнёт использовать их в генерируемых описаниях сцен.
